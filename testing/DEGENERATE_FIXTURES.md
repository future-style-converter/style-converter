# Degenerate-fixture audit (Auditor rounds 16-22)

A fixture is "degenerate" when the property under test has no observable
visual effect because the fixture lacks the context the property requires
(SVG element, list markup, scrollable parent, animation timeline, etc.).
Cross-platform SSIM still passes ≥0.95 because all variants render to
identical empty boxes.

## Why this matters

The Tier 1 banner says "490/550 passing (89.1%)". Of those 490:
- ~102 (20.8%) are PROVABLY degenerate by category-context analysis
- Auditor random spot-sampling (rounds 20+21) found 8.5/10 (85%) degenerate
  in their picks — implying real degeneracy may be far higher than 102

Real meaningful coverage estimate: probably 90-388/550 depending on how
strict you are about "context required to test".

## Resolution paths

Per-fixture rewrite (already done for 6: JustifySelf, MixBlendMode,
PerspectiveOrigin, FlexDirection, Right, MaskComposite). Each requires
manual fixture authoring — there's no template that works for all 102
because each property needs its specific context.

Bulk reclassification: mark all 102 as `needs-context` in tracker so the
"passing" status doesn't claim more than it can deliver.

## Why not rewrite all 102?

- SVG fixtures need a real `<svg>` element with `<path>` / `<circle>`
  child — not currently representable in the fixture format (no SVG
  tag in the IR component model).
- Animation fixtures need keyframe state (Tier 4 territory) — static
  SSIM cannot validate timing properties.
- Scrollable fixtures need overflowing content + scroll-state — the
  test harness doesn't drive scroll position.
- Table fixtures need `<table><tr><td>` markup — IR has no table tag.

Many are architectural mismatches between the fixture format and what
the property requires, not laziness. Honesty path: mark as `needs-context`
and treat as "covered to the extent the harness can".
