# Cross-platform screenshot testing

A three-way visual comparison system for iOS / Android / Web SDUI renderers.

Each platform captures chromeless per-component PNGs onto an identical
canvas. A single Node script compares them pixel-by-pixel and perceptually
(via SSIM), then emits an HTML report + machine-readable manifest.

## Quick start

From the repository root:

```bash
./test-all.sh                        # uses examples/visual-test.json
./test-all.sh examples/foo.json      # different input
```

The script:

1. Runs the Gradle converter → `out/tmpOutput.json`
2. Syncs IR into every platform bundle
3. Builds + launches iOS on a simulator, pulls captures (skipped if no Xcode)
4. Configures the Android emulator + installs the APK, pulls captures (skipped if no adb)
5. Starts a Vite server in capture mode + runs Puppeteer, writes captures
6. Generates `testing/report/index.html` and opens it

Every platform step is independently skip-able — if you don't have an
Android emulator attached, `test-all.sh` still runs iOS + Web and the
report shows placeholders for Android.

## The capture contract

All three platforms render each component onto an identical surface:

| property     | value                         |
| ------------ | ----------------------------- |
| width        | **exactly 390 px**            |
| height       | natural (no clamping)         |
| background   | solid `#1A1A2E` (no alpha)    |
| padding      | 16 px on all sides            |
| scale        | 1 px = 1 logical pixel        |
| chrome       | none — no header / footer / border / label |

Output file naming is shared: `{index}_{ComponentName}.png`
(e.g. `023_Shadow_Simple.png`). The index + name come from the flattened
component walk of `tmpOutput.json`; every platform walks the IR in the
same order.

### Where "chromeless" is implemented

- iOS:     [`StyleConverterTest/Screenshot/CaptureCanvas.swift`](iOS/StyleConverterTest/Screenshot/CaptureCanvas.swift)
- Android: `CaptureCanvas` composable in [`ScreenshotCaptureScreen.kt`](Android/app/src/main/java/com/styleconverter/test/screenshot/ScreenshotCaptureScreen.kt)
- Web:     [`src/ui/CaptureGallery.tsx`](web/src/ui/CaptureGallery.tsx) (reached via `?mode=capture`)

If any of these drifts from the 390-wide / #1A1A2E / 16-padding contract,
the cross-platform diff is no longer meaningful.

## Comparison metrics

Per pair (iOS↔Android, iOS↔Web, Android↔Web) the report records:

- **SSIM** (Structural Similarity, via [ssim.js](https://www.npmjs.com/package/ssim.js)):
  a perceptual metric from 0 to 1. Tolerates subpixel font AA; catches
  real structural differences. Thresholds:
  - ≥ 0.97 → considered **identical** in the summary count
  - ≥ 0.90 → not flagged as "diff" in the row header
  - ≥ 0.85 → yellow warning tier
  - < 0.85 → red (clearly different)

- **Pixel mismatch %** (via [pixelmatch](https://www.npmjs.com/package/pixelmatch)):
  percent of pixels whose color differs beyond an AA-aware threshold.
  Useful for drill-down but not a primary summary because platform font
  rendering routinely eats a few percent.

- A **red-overlay diff PNG** showing where the mismatches are. Handy when
  SSIM tells you "these differ" but you need to see *where*.

When run with `--baseline`, each platform's current capture is ALSO diffed
against its committed baseline in `testing/baseline/`. A row is marked
"regressed" if any platform drops below the thresholds.

### B-FOUNDATION multi-metric upgrade (round 90+)

In addition to SSIM + pixelmatch, every pair now records six secondary
metrics (per `testing/COMPARE_METRICS.md`):

- **DSSIM** — `1 - SSIM`, easier to compare across small diffs.
- **Per-channel SSIM** — separate SSIM scores for R/G/B/A. Catches
  channel-specific drift (e.g. an alpha bug that doesn't move overall SSIM).
- **Edge SSIM** — SSIM run after a Sobel edge filter. Goes to 0 when one
  platform smudges a sharp boundary the other preserves.
- **Histogram KL divergence** (per channel) — measures how much the color
  *distribution* shifts independent of position.
- **pHash + Hamming distance** — perceptual hash; small Hamming
  (≤ 4) means "globally similar layout even if pixels differ."
- **LAB ΔE2000** — perceptual color difference in CIE LAB space, with
  mean / max / p95 reported. Stride-1-in-4 by default; `--full-lab` to
  exhaustively sample every pixel.

A 10-label **divergence classifier** (`testing/classify-divergence.mjs`)
maps every pair into `test-not-applicable | no-content | identical |
sub-pixel-noise | glyph-metric-noise | color-drift | edge-shift |
structural-divergence | mixed | unknown` based on these metrics.
`no-content` is the round-91 pre-classifier gate that fires when either
side of the pair has < 5% foreground coverage vs the canonical #1A1A2E
capture background — surfaces empty-extraction false positives
(pilot-001) that the per-pair metric tree would otherwise mislabel as
structural-divergence / mixed / sub-pixel-noise. `test-not-applicable`
(FIX-E) is the highest-severity pre-gate, fires when
`metrics.wptNotApplicableTags` is a non-empty array (populated by
`testing/titan/inject-wpt-block.mjs` from the auto-bucketer's
`notApplicable` tags in `testing/wpt-buckets.json`), and reclassifies
tests that the architectural-exclusion scanner already flagged as
out-of-scope for Compose/SwiftUI — without this, ~3,676 W4 tests still
scored as `mixed` / `structural-divergence` / `no-data`, defeating
FIX-D's projected 1,471 reclassifications. `glyph-metric-noise`
(swarm-002) rescues small styled-text WPT tests whose pHash hamming
distance trips the structural-divergence gate purely because the
harness's 390x~62 fit-content capture is being diffed against the
browser-ref's 390x600 full-document canvas — the two text strips hash
apart while edgeSsim, labMean, and pixelPct all agree the renderer
is correct (~1,455 W5 tests flip). The HTML report shows each pair's
label as a colored badge; `testing/baseline-stats.mjs` writes the
empirical distribution to `testing/baseline-stats.json` for tracking
how the platform-pair population shifts across rounds.

The legacy SSIM thresholds remain the regression gate (Phase A). Phase B
(log-only) warns when a label downgrades baseline-vs-current; Phase C
(future) will gate on distribution shifts.

## Audit infrastructure

Beyond the per-fixture `test-all.sh` flow, the campaign added five
self-validating audit harnesses, each catching a different class of
regression. The unified entry point is `testing/smoke.sh`:

```bash
./testing/smoke.sh           # full ~5-7 min: unit + Tier 5 + Tier 11 + BASELINE
./testing/smoke.sh --quick   # ~60-90s web-only: unit + Tier 5 + Tier 11
```

Output is a combined pass/fail summary across all sections. Trap-based
vite cleanup ensures no orphaned dev servers even on script-error or
ctrl-C.

| `bash testing/doc-staleness-check.sh` | doc-quoted numbers drifted from live source-of-truth scripts | ~5s |
| `bash testing/loops/audit_rewrite_claims.sh` | tracker-claim fabrication ("REWRITTEN" without real fixture/commit) | ~1s |
| `node --test testing/*.test.mjs testing/titan/*.test.mjs` | broken adapter logic across 15 testing-side scripts (448 unit tests across css-to-ir, a11y-audit, os-matrix, interaction-states, compare-screenshots, classify-divergence (FIX-E `test-not-applicable` pre-gate + 8-tag-routing pins + swarm-002 `glyph-metric-noise` gate), compare-screenshots-text-metrics (B-EXT B8/B9/B10), classify-text-probe, capture-url, titan/extract-fixture (with bug-1..5 regression-pin tests + EXTFIX-A nested-children + _text contract), titan/capture-browser-ref, titan/aggregate-sections, titan/wpt-not-applicable (FIX-D 40 architectural-exclusion rules — 17 swarm-001 + 12 swarm-002 + 11 swarm-003), titan/render-titan (TITAN dashboard helpers — URL builder, label-color picker, manifest aggregator), titan/inject-wpt-block (F-HARNESS swarm-002 RC2: vertical PNG stitcher for multi-component WPT diffs)) | ~80ms |

| `node testing/baseline-stats.mjs` | post-classification of every pair into 10 divergence labels (test-not-applicable / no-content / identical / sub-pixel-noise / glyph-metric-noise / color-drift / edge-shift / structural-divergence / mixed / unknown); writes `testing/baseline-stats.json` for distribution tracking | ~1s |

them fail-fast: unit tests first (cheapest, catches bugs in adapter

least 2 iOS Simulator runtime versions installed. See
`testing/TIER12_OS_MATRIX.md`.

For the historical context of why each harness exists, see
`testing/CAMPAIGN_SUMMARY.md` (each round 40-56 added one piece of this).

For the recurring failure patterns the campaign discovered (degenerate

including symptoms / root causes / how to spot / how to fix — see

## Commands

```bash
# Full run: convert → capture every platform → generate report.
./test-all.sh

# Capture without re-building one of the platforms
SKIP_IOS=1 ./test-all.sh
SKIP_ANDROID=1 ./test-all.sh
SKIP_WEB=1 ./test-all.sh

# Update baseline from the current captures (do this after an intentional
# visual change, e.g. adding a new IR property).
UPDATE_BASELINE=1 ./test-all.sh

# Compare against baseline and exit non-zero if anything regressed.
# Intended for CI.
BASELINE=1 ./test-all.sh

# Run an unattended (TITAN-style) capture that NEVER steals laptop focus:
#   - iOS Simulator boots headlessly (no Simulator.app window)
#   - Android emulator boots with -no-window (auto-launched if none running,
#     auto-torn-down at end unless EMULATOR_KEEP=1)
#   - Web capture runs headless Chrome (default)
#   - The HTML report is NOT auto-opened at the end
BACKGROUND_MODE=1 ./test-all.sh

# Pin a specific Android AVD (otherwise we use the first one returned by
# `emulator -list-avds`). Only relevant when no device/emulator is already
# attached — if you have one running we never touch it.
EMULATOR_AVD=Medium_Phone_API_36.1 ./test-all.sh

# Leave the Android emulator running after the run (only meaningful when
# WE booted it; pre-existing emulators are always left alone).
EMULATOR_KEEP=1 ./test-all.sh

# Just re-generate the report from existing captures (no rebuild)
( cd testing && node compare-screenshots.mjs )
( cd testing && node compare-screenshots.mjs --baseline )
( cd testing && node compare-screenshots.mjs --pixel-threshold 1 --ssim-threshold 0.98 )

# Capture a single platform manually
( cd apps/web-harness && node capture-screenshots.mjs --url http://localhost:3000 )
```

## Interpreting a report row

Each row is one component. From top to bottom you see:

1. **Filename + badges** — warn badge appears when platforms captured at
   different heights (common when iOS is missing a property that adds
   visual weight — e.g. outline increases Android's height but not iOS's).

2. **Three platform images** — iOS, Android, web side-by-side.

3. **Three pairwise diffs** — each shows SSIM, Δpx, and a red-overlay
   image highlighting differing pixels. The left border of each cell is
   color-coded:
   - green = SSIM ≥ 0.97 (perceptually identical)
   - yellow = 0.85 ≤ SSIM < 0.97 (noticeable but usually AA / font)
   - red = SSIM < 0.85 (real rendering disagreement)

4. **Baseline comparison** (only with `--baseline`) — each platform's
   current capture vs its committed baseline. Marked `regressed` if any
   drops below the thresholds.

Use the "Show only components with diffs" checkbox at the top to narrow
down to rows flagged `has-diff`.

## Troubleshooting

- **iOS build fails with "CaptureCanvas not in scope"**: delete
  `testing/iOS/StyleConverterTest.xcodeproj/` and re-run — XcodeGen
  re-picks up new files. `test-all.sh` does this automatically.

- **Android captures come out at 358×N instead of 390×N**: check the
  emulator's `wm size` / `wm density` — the canvas measurement assumes
  1px = 1dp (density 160). `test-all.sh` sets this.

- **Web capture times out**: the Puppeteer script waits for a
  `data-capture-ready` sentinel emitted by `CaptureGallery` after all
  canvases render. If the gallery fails to load (check
  `apps/web-harness/public/ir-components.json`), no sentinel means timeout.

- **"Maximum update depth exceeded" in capture console**: the hot-reload
  hook used by the dev gallery needs a memoized callback. Capture mode
  disables hot-reload (see `App.tsx`) so you shouldn't see this during
  captures.

## Adding a new platform

1. Implement a chromeless capture mode that respects the contract above.
2. Write captures as `{index:03}_{ComponentName}.png` into a new
   directory under `testing/`.
3. In [compare-screenshots.mjs](compare-screenshots.mjs), extend the
   `PLATFORMS` array and the `paths` map.
4. Update the HTML `renderRow` to include the new column.
5. Extend `test-all.sh` with a matching capture step.
