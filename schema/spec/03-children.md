# IR v1 — 03: Children (map in, array out)

**Status: normative.** Nested children are part of the v1 wire format.
The flat-IR v2 redesign (slot/placement) is a **planned major version**,
referenced here for orientation only — nothing in this section implements
it (see 05-versioning.md).

Implementing code:

- input side: `converter/src/main/kotlin/app/parsing/css/CssParsing.kt`
  (`parseComponent` reads `children` as a JsonObject map;
  `convertToIR` flattens map → list)
- output side: `converter/src/main/kotlin/app/irmodels/IRDocument.kt`
  (`IRComponentSerializer` emits `children` as a JSON array,
  omit-when-null-or-empty)
- producer of the map form: `tools/titan/extract-fixture.mjs`
  (`buildComponents.buildNode` — children stored as an id-keyed map,
  explicitly matching the Kotlin parser's `jsonObject.mapValues` read)

## The contract

**Authoring/extractor input** ships children as a **name→component map**
(preserving stable extractor ids like `color-001__1__0` as keys):

```json
{ "components": { "Parent": {
    "properties": { "display": "flex" },
    "children": {
      "child__0": { "properties": { "width": "50px" },
                    "children": { "grandchild__0__0": { "properties": { "height": "10px" } } } }
    } } } }
```

**Converter output (the IR v1 wire)** ships children as an **array of
full components**, recursively, at every depth:

```json
{ "components": [ { "id": "parent-001", "name": "Parent",
    "properties": [ { "type": "Display", "data": "FLEX" } ],
    "children": [ { "id": "child__0-002", "name": "child__0",
        "properties": [ … ],
        "children": [ { "id": "grandchild__0__0-003", "name": "grandchild__0__0", "properties": [ … ] } ] } ] } ] }
```

Rules (all from `convertToIR` + `IRComponentSerializer`):

1. The child's **map key becomes its `name`** — the original extractor id
   survives verbatim in `name`, while `id` is regenerated by the
   converter's global counter (`<lowercased-name>-<NNN>`, zero-padded,
   depth-first, shared across the whole document).
2. Children are **full components** — they can carry their own
   `properties`, `selectors`, `media`, `_text`, and further `children`.
3. `children` is **omitted** when null or empty. Present ⇒ non-empty
   array. The wire never contains `"children": []` or `"children": {}`.
4. Renderers consume the array positionally
   (`IRComponent[]` in `runtimes/web/src/core/ir/IRModels.ts`,
   `List<IRComponent>?` in
   `runtimes/compose/src/main/java/com/styleconverter/runtime/core/ir/IRModels.kt`,
   `[IRComponent]?` in
   `runtimes/swiftui/Sources/StyleConverterRuntime/Models/IRModels.swift`).
   Source order in the input map is preserved.

## Why the asymmetry exists

The extractor keys children by id so fixture diffs stay readable and the
Kotlin parser can address children stably; renderers need positional
arrays for layout. `convertToIR` is the single flattening point, so the
renderer-facing contract stays array-shaped everywhere.

## Planned change (v2, not implemented here)

Flat IR with explicit `slot`/`placement` references — children move out
of the component body into a flat component table plus a placement list.
That is a **breaking (major) change** and lands only with the v2 freeze,
gated by the versioning rules in 05-versioning.md. Until then, any tool
that flattens the tree must do so internally; the wire stays nested.
