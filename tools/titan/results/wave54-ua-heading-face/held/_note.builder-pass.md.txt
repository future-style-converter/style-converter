## What changed and why

**The defect (wave53-final, looked at):** both natives paint author-unsized headings at the 16 px regular body face
where the ref paints the UA `2em/1.5em/1.17em bold` face.
- Android `css-break/block-in-inline-015-print` f 0.9489: four 16 px regular lines (bands 9–12 px, right edges x42–53)
  against the ref's four bold lines (18–25 px, x72–96). iOS passes the same IR at P 0.9894 because it has the rule.
- `text-decoration-inset-005/-006` ios/android: ONE 16 px line, sup raised and sub lowered inside it (the fold IS
  engaged), where the ref wraps a 2em bold paragraph onto two lines ("…b(row)n" / "fox").
- `inset-014` ios/android: the right 16ch two-line wrap at 13 px where the ref paints 26 px bold monospace.
- `inset-011` (control): Arabic runs stacked, no colored underlines (the fold refuses). Unchanged by design.

**Mechanism (traced; agrees with the brief, verified on the tree):**
- Compose had no UA font step: `ComponentRenderer.kt` :1141 ran `ListStyleUaRule.apply` as the only tag-keyed rule.
- iOS `UAElementFontRule.headingAppliesTo(hasElementChildren:)` stood the heading half down for every heading with
  children (wave-40 measurement on the pre-fold STACKED render).
- Fold admission never reads FontSize/FontWeight (brief §4 D) — now PINNED on both natives (soundness pins below).

**U1-android (Compose):**
- NEW `runtimes/compose/src/main/java/com/styleconverter/runtime/typography/UAElementFontRule.kt` (198 lines) —
  `UAElementFontRule.apply(sourceTag, own, merged, standsDown)`: h1…h6 `2/1.5/1.17/1/.83/.67` + bold, sub/sup
  `1/1.2`; em base `DynamicValueResolver.fontSizePxOf(merged) ?: MonospaceUAFontSize.resolveSp(merged) ?: 16`; the
  author's own FontSize/Font/FontWeight wins; in-place substitution; returns the SAME list instance when nothing fires.
  FontWeight is emitted as the INTEGER `{"weight":700}` (ValueExtractors/TextStyleApplier read `intOrNull`; a 700.0
  double reads as null — mutation M4 proves the pin catches it).
- NEW `…/typography/UAHeadingFoldGate.kt` (105 lines) — `standsDown(component, mergedPreUa)`: false for a leaf;
  true for a non-heading with children (the old flag, never read); for a heading with children, true unless
  RenderContent would resolve a run plan (runs present, host not `position: relative`) AND `InlineRunFold.fold` on it
  returns `Folded`. Host lang = `component.lang` (what RenderComponent provides as LocalContentLanguage, verbatim).
- seam-1 (below) hoists the ListStyleUaRule result into `listUaProperties` and wraps it in the UA font step, BEFORE
  DynamicValueResolver (:1206), so `ch`/`em` on the heading resolve against the UA face.

**U2-ios (SwiftUI):**
- NEW `runtimes/swiftui/Sources/StyleConverterRuntime/StyleEngine/typography/UAHeadingFoldGate.swift` (85 lines) —
  `standsDown(component:inFlowChildren:mergedPreUA:)`: same predicate, calling `InlineRunFlow.fold` with the call
  site's inputs (`FlexboxApplier.sorted(inFlowChildren)`, total child count, `meta.lang`).
- seam-2 (below): the `hasElementChildren:` argument of `UAElementFontRule.apply` in `mergedProperties(now:)` becomes
  the gate's verdict.
- `StyleEngine/typography/UAElementFontRule.swift`: DOCS ONLY (verified: `git diff` has no non-comment line) — TWIN
  STATUS re-trued (ported), `headingAppliesTo` re-dated (the wave-40 table kept as the stacked-render record, the
  wave-54 narrowing stated), the `hasElementChildren` parameter doc.

**Where the tree and the brief disagree (tree wins):**
- Brief: `standsDown(component, mergedPreUa, lang)`. Tree: the lang the renderer hands the fold is the host's own
  `component.lang` (LocalContentLanguage is provided verbatim per component, never `?:`-chained — ComponentRenderer.kt
  :270-292), so the Kotlin gate takes no lang parameter.
- The Compose renderer suppresses the run plan for a `position: relative` host (RenderContent :3366); the gate mirrors
  that (pinned). The WPT float/atom packer suppressions (:3371-3373) are NOT mirrored: those members are refused by the
  fold's own member ring anyway, and no corpus heading host reaches them (census).
