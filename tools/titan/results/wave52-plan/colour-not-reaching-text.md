## 3. Mechanism, with file:line

**A. 052 — `all: <kw>` drops the element's OWN later declarations (runtime, all three platforms).**
IR (`sections/css-cascade/per-test-ir/wpt__css-cascade__all-prop-initial-color.json`): `p` carries `Color red`; the `span` child carries `[{type:"All",data:"INITIAL"}, {type:"Color", srgb 0/0.502/0}]` in SOURCE order — the extractor's unlayered bag is written in cascade order (`extract-fixture.mjs:6327 assignDeclarations`), and the converter preserves it. css-cascade-4 §3.1: `all` is a shorthand for every longhand except `direction`/`unicode-bidi`; §6.4 order of appearance: `all: initial; color: green` in one block computes `color: green`. The runtimes are order-blind:
- Compose `core/renderer/ComponentRenderer.kt:1134-1137` — `allReset = rawProperties.firstOrNull { it.type == "All" }` … `unresolvedProperties = if (allReset != null) emptyList() else rawProperties` — every declaration, own and inherited, gone; `typography/TextStyleApplier.kt:132` never sees a `Color`, `:229` falls to `Color.Unspecified` → black.
- iOS `StyleEngine/global/GlobalExtractor.swift:41-49` `applyingAllReset` returns `[]` when any `All` keyword is present; called at `Renderer/ComponentRenderer.swift:340` on the MERGED list (`InheritedText.merge`, `Renderer/InheritedText.swift:100-125`, prepends inherited under own). `GlobalConfig.swift:5-9` documents itself as inert.
- Web `engine/global/AllApplier.ts:4-6` emits `{ all: 'initial' }`; `core/renderer/StyleBuilder.ts:151` inserts `color` (applyTextColor) and `:222` inserts `all` LAST (applyGlobalPhase10, `engine/global/_dispatch.ts:6-8`). The object is consumed in key order — inline `style` at `renderer/NodeRenderer.ts:67`, stylesheet path `core/renderer/RuleBuilder.ts:86,104` via `CssText.ts:68 Object.entries` — so the browser applies the `all` shorthand write AFTER `color: green` and resets it, and resets `font-family` too (the serif face in the capture). CSS-wise the DOM string `color:green; all:initial` genuinely means black; the runtime built the wrong declaration order.

**B. 055 — the post-load overlay cannot introduce `color` (extractor; runtimes faithful).**
`post-load-extract.mjs:286` lists `'color'` in `POST_LOAD_COMPUTED_PROPERTIES`; `:359 color: { repairOnly: true }`; `:1358 if (rule?.repairOnly && props[name] === undefined) continue;` (wave-44 H2: "correct a static assertion, never make one"). The static pass ran on the PRE-script DOM, where `p:nth-child(even of .c)` (of-selector branch `extract-fixture.mjs:5845`) matched p[3] and p[5]; the script toggles `.c` off p[3], so the LIVE matches are p[4] and p[6]. Result in the IR: components `__3` and `__5` carry `Color rgb(0,0,0)` (repaired to the live black — correct), `__4`/`__6` carry NO `Color` (nothing to repair — wrong). `rePseudoFromLivePage` (`:1127-1159`) already re-extracts the whole fixture from the settled DOM but "Only its `_pseudo` bags are consumed" (`:1145-1147`). The runtimes paint exactly the IR (no `Color` → inherit → black): not a runtime defect. The `-prefix` / `nth-child-of-attr` / `-id-prefix` twins show the same all-black picture for a second reason: `parseCompound` rejects any `[`-attribute compound (`extract-fixture.mjs:5070`), so the static side never had a `color` key to repair either.

**C. 087 — `::first-letter` is dropped at parse time (extractor; runtimes faithful).**
`extract-fixture.mjs:5000 SUPPORTED_PSEUDO_ELEMENTS = {before, after, marker}`; `:5098-5104` any other `::name` → `unsupported = true` → the rule is dropped before extraction; the one-colon alias (`:5043`, `:5125-5131`) resolves identically. IR: one component, text "First letter should be green", no `Color`, `lossyReasons: ['inline-run-merged']`. No runtime can paint the F green from that document. css-pseudo-4 §2.2: the first letter is the first typographic letter unit of the first formatted line, empty inline boxes are skipped (the test's whole point), leading punctuation is included.

## 4. Proposed fixes (cheapest first)

**F1 — order-aware `all` reset, all three runtimes (S per platform, shared spec).** One rule, byte-parallel on the three: over the element's OWN list find the LAST `All` entry at index i (css-cascade-4 §6.4 — a later `all` wins over an earlier one); DROP own[0, i) except `Direction` and `UnicodeBidi` (§3.1 exemption; all-prop-001 is the carrier); KEEP own(i, end] verbatim; then the inherited channel: `INITIAL` → drop it (every property takes its initial value, §7.3.1); `INHERIT` / `UNSET` → keep it (§7.3.2; §7.3.4 makes `unset` = inherit for inherited properties, and the channel only carries inherited types — Compose `INHERITED_PROPERTY_TYPES` `ComponentRenderer.kt:174`, iOS `InheritedText.inheritedTypes`); `REVERT` / `REVERT_LAYER` → keep it (§7.3.3 rolls back to the user/UA origin, where inherited properties inherit). Then remove the `All` entry itself.
- Compose: replace `:1134-1137` with a pure `global/AllReset.kt` (`apply(own, inherited): Pair<List, List>`) evaluated BEFORE `mergeInherited` (`:826-844`) on `schemeResolvedProperties` + `inheritedProperties` — the reset must see own and inherited separately, which the current post-merge position cannot.
- iOS: `GlobalExtractor.applyingAllReset(own:inherited:)` twin; move the call at `ComponentRenderer.swift:340` from the merged list to `ownProperties`/`inheritedTextProperties` before `InheritedText.merge`.
- Web: `engine/global/_dispatch.ts` gains `applyAllReset(properties)` (the own-list half of the same rule; the browser does the inheritance half natively) and StyleBuilder applies it FIRST: filter `properties` through it at `:129` and emit `all` as the FIRST key so every later key re-sets what the shorthand cleared. CSS-correct on web too: `all:initial; color:green` is the source's own order. Font caveat: `all: initial` legitimately resets `font-family` on web; the harness browser's UA-initial face is the narrow serif measured above (213 vs 253 px) while the ref's is Inter-width, so the web cell stays face-divergent after the colour fix (see §9).

**F2 — introduce-when-differs-from-parent for `color` in the post-load overlay (S).** `post-load-extract.mjs:1358`: when `props.color === undefined`, write the computed value iff it differs from the PARENT record's computed `color` (both are `rgb()` strings from one `getComputedStyle`, so textual equality IS semantic equality here — the H2 objection at `:352-357` was about `green` vs `rgb(0,128,0)`, which cannot arise parent-vs-child). Rationale: css-color-4 §3.2 `color` is inherited, so a child computed value that differs from its parent's exists only through a declaration cascaded onto the child — precisely the fact a stale static bake misses, and selector-agnostic (fixes the attribute-selector twins too). Plumbing: `mergePostLoadIntoFixture` (`:1386`) has every record with `path`; build `Map(path.join('.') → record)` and pass `{ parentStyles }` into `overlayComputedOnComponent` (`:1325`); the root's parent is the body record. Skip the tag set `a, button, input, select, textarea, mark` (UA colours the runtime models separately, e.g. `uaLink` at `extract-fixture.mjs:10808`) — 17 post-load tests carry them (census `postLoadTestsWithUaColouredTags`). Wider alternative (not recommended this wave): adopt the re-extracted FLAT bag from `rePseudoFromLivePage` as the static base for every post-load test — repairs every stale selector match, but rewrites 277 fixtures and sits on the `cascade-and-splitter` lane's seam.

**F3 — `::first-letter` as a synthetic inline run (L; extractor-only if gated).** In `parseCompound` accept `first-letter` (`:5000`), route its declarations to `_pseudo['first-letter']`, and in `buildComponents` split the host's leading text per css-pseudo-4 §2.2 (skip empty inline descendants, include leading punctuation, one grapheme) into a `span`-tagged child carrying the bag's properties plus `meta.runs: [{child}, {text: rest}]`. All three runtimes already fold a Color-only span member inline — Compose `typography/inline/InlineRunFold.kt:72-78` (wave-47 styled-span ring), iOS `StyleEngine/typography/inline/InlineSpanRing.swift:29-33`, web natively. GATE: emit the run only when the bag holds ring-admitted properties (`Color`, `FontWeight`, `FontStyle`, `TextDecorationLine` underline/line-through); `float`, `font-size`, `background*`, `border*` bags keep today's drop with a new `first-letter-unsupported` lossy marker — a stacked "F" on iOS/Compose would be worse than black. Option B (runtime SpanStyle from a `_pseudo['first-letter']` bag on three renderers) is the complete answer and out of budget.
