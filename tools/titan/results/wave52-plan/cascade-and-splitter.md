## 4. Proposed fixes

**F1 — importance-aware collapse (0(a′)).** In `parseCss` (:1158-1203) and the inline bag (:6298-6310): make `assignDeclaration` return whether the write was taken; add one guard before it — if `important[k]` is already true and `!bang`, refuse (css-cascade-5 §6.1 "Cascade Sorting Order": importance is compared before order); when the write is taken set `important[k] = bang` (clears a stale flag instead of the `props[k] === v` probe at :1203). Cross-rule: widen the :6318-6320 gate with `|| matchedRules.some(r => r.important) || Object.keys(inlineImportant).length > 0` so a document that carries importance is resolved by the existing §6.4.4-ordered sort (unlayered rules all take rank `layerCount`, so normal-vs-normal ties fall to document order — byte-identical to today's last-wins; only important-vs-normal changes). Do F3 first or in the same lane, because the layered resolver is oracle-less until F3.

**F2 — one css-syntax-3 splitter (0(a″)).** Lift `splitDescriptors` (:8308) to a shared `splitDeclarations(body)`: `;` separates only at paren depth 0, outside a `<string-token>` (§4.3.5) and outside an unquoted `<url-token>` (§4.3.6: `url(` not followed by a quote consumes to the matching `)`), with backslash escapes consumed as a pair inside AND outside strings (§4.3.7). Use it at :1158, :6298, :7095 and :8374. Two gotchas measured on this corpus (`splitter-differential.json` `method`): comments must be stripped BEFORE splitting (an apostrophe in `/* doesn't */` otherwise opens a string — 19 tests), and `view-transition-name: secon\'d` (`css-view-transitions/escaped-name`) is an escape, not a quote. `parseCss` receives comment-stripped CSS already (`stripComments`, imported by `post-load-extract.mjs:108`) — verify the :6298 style-attribute path does too.

**F3 — candidate filter in the layered sort (0(a‴)).** In `resolveOne` (:1287-1299), skip a candidate whose `provablyInvalidDeclaration(name, value)` is non-null WHEN at least one other candidate for that name (and rank window) is not provably invalid — the exact `assignDeclaration` semantics (:962-975), so the all-invalid case still ends on the sort's own winner and byte parity holds. `revert-layer` is a keyword and never trips the oracle. Log via `invalidShadowDrops` like every other refusal.

**F4 — exponent + case in AngleParser (0(e)).** `AngleParser.kt:24` → `^([+-]?(?:\d+\.?\d*|\.\d+)(?:[eE][+-]?\d+)?)(deg|rad|grad|turn)$` with `RegexOption.IGNORE_CASE` (css-values-4 §5.3 admits the exponent; css-syntax-3 §4.3.13 folds it into the `<number-token>` before §4.3.3 attaches the unit). Then re-point the three Raw pins: `InvalidDeclarationDropTest.kt:131-145` must assert `LinearGradient` with `angle.degrees == 45.0` instead of `Raw`; the gradient guard comment at `GradientPrefixGuard.kt:117-125` ("AngleParser cannot read the exponent yet") becomes stale and must be rewritten. `parseHslHue` needs no change once F4 lands (`AngleParser.parse` resolves first), but gets its own pin (section 7).
