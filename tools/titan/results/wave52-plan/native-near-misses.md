### 3.1 T1 — the harness root-stack fold joins an abspos root's margin into the §8.3.1 collapse set (6 cells, 2 lines per platform)
IR (`per-test-ir/…clip-path-ellipse-006.json`): root 0 = `<p>` with NO properties (UA `margin: 1em 0`), root 1 = `position:absolute; margin:50px; width 150; height 100; clip-path: ellipse`. No inset → the wave-18 RC1 static-position root. Chrome: p bottom margin 16 + own margin-top 50 = 66 below the line box (52) → 118. Natives: `max(16, 50)` = 50 → 102. Code: `apps/android-harness/app/src/main/java/com/styleconverter/test/screenshot/ScreenshotCaptureScreen.kt:1585-1641` builds the root's `RootStackMargin` from `StaticEmMargin.verticalEdges(root.properties)` and flags it `marginTransparent = staticPos` with the comment "its own declared margins join the collapse-through set (§8.3.1's empty-box model …)"; `UaBlockMargins.kt:207-243` (`collapsedRootStackGapsPx`) then does `runningMax = max(runningMax, plans[i].topPx)` for the transparent root. iOS twin: `apps/ios-harness/StyleConverterTest/Screenshot/CaptureCanvas.swift:414-434` ("Its OWN declared margins join the collapse-through set") + `runtimes/swiftui/Sources/StyleConverterRuntime/StyleEngine/spacing/ComposedRootStack.swift:272-300`. CSS 2.1 §8.3.1: "Margins of absolutely positioned boxes do not collapse (not even with their in-flow children)"; §10.6.4/§10.3.7 static position = where the box's top MARGIN edge would be in flow, then its own margin applies. **Fix**: for a `staticPos` root contribute `(0, 0)` to the fold (like the hoisted branch at `:1582`) and do NOT strip its declared margins (render them on the box: the anchor is the flow position, the margin offsets the ink). Same two lines in `CaptureCanvas.swift:431-434`.

### 3.2 T2 — an EMPTY in-flow root does not collapse through (2 cells, + `text-decoration-propagation-04` android f 0.9439 as a maybe)
IR (post-load): three ROOTS — `<p>` `height:0; margin:16px 0` (empty), the text block, another empty `<p>`. §8.3.1: "If the top and bottom margins of a box are adjoining, then its margins collapse through it" (zero height, no border/padding, no content) → ONE 16-px gap; natives emit 16 + 16. Code: the fold only marks RC1/hoisted roots `marginTransparent` (`ScreenshotCaptureScreen.kt:1641`, `CaptureCanvas.swift:414`); an empty opaque root closes the set (`UaBlockMargins.kt:236-239`). The runtime's CHILD path has the same hole for nested cases: `runtimes/compose/…/core/renderer/ComponentRenderer.kt:670-671` `SELF_COLLAPSE_HEIGHT_TYPES = setOf("Height", …)` treats a DECLARED `height: 0` as a floor (§8.3.1 says "zero or auto computed height" self-collapses), and `:560-561` bails the whole plan ("self-collapsing child", pin S12); twin `runtimes/swiftui/…/StyleEngine/spacing/MarginCollapseChildGates.swift:74-95` + `MarginCollapsePlanner.swift:135-137`. **Fix (roots, cheap)**: `marginTransparent = staticPos || isSelfCollapsingRoot(root)` (no text, no children, `Height` absent or 0, `MinHeight` absent or 0, zero block borders/padding, not out-of-flow) — the fold already implements the n-ary max for transparent roots. **Fix (children, medium)**: make `Height == 0` not a floor and let a self-collapsing child contribute `max(top,bottom)` to the running set instead of bailing (both natives + the S1–S12 pin table).

### 3.3 T3 — the RC1 static-position root paints in slot order, below later in-flow roots (2 cells)

### 3.4 T4 — the vertical block-flow seam's BAKED-LAYOUT guard fires on author-declared `width`+`height` (1–2 cells)

### 3.5 T5 — `backface-visibility: hidden` culls the whole subtree under `transform-style: preserve-3d` (2 cells)
IR: parent `rotateY(180deg); backface-visibility: hidden; transform-style: preserve-3d; width 100` → child `100×100 green; will-change: transform`. css-transforms-2 §10: the property hides the ELEMENT's back face; in a preserve-3d context the child is its own plane and keeps `backface-visibility: visible`. Code: `runtimes/compose/…/StyleApplier.kt:532-556` → `result.alpha(0f)` on the element modifier chain (children included); iOS `TransformsApplier.swift:174-177` → `v.opacity(0)` on the composed content. **Fix**: when the culled element has `TransformStyle == PRESERVE_3D`, suppress its OWN background/border painting instead of alpha-ing the subtree (Compose: skip BackgroundApplier/BorderApplier for that node; iOS: draw children without the culled box's decoration). Census G: this is the ONLY `preserve3d:true` carrier with children; the 11 flat carriers keep today's behaviour.

### 3.6 T6 — abspos root/child with an inset and a UA-margin tag: `top` applied to the border edge (3 cells)
IR: `<p position:absolute; top:0; left:8>` with no declared margins. CSS 2.1 §9.3.2: `top` offsets the MARGIN edge; the UA `p` margin (16) sits between. Code: UA block margins exist only in the fold (`UaBlockMargins.kt:53`, `spacing/UaBlockChildMargins.kt`) and the fold skips out-of-flow roots (`ScreenshotCaptureScreen.kt:1624` → `staticEdges = null` → R4/R5 at `UaBlockMargins.kt:365-372`), while the out-of-flow capture branch (`ScreenshotCaptureScreen.kt:1063-1075`) anchors the inset at the padding edge with no margin. **Fix**: synthesise the UA vertical margin for an inset abspos root whose tag is in the UA table and whose block margins are undeclared, and add it to the inset offset (both harnesses). `-005`'s `<p>` is a CHILD of a `display: table-cell` body-root — same rule but in the runtime's abspos placement; lower confidence.
