### Where the tree / my build differs from the brief (the tree wins; each is narrower or a correction)
1. **Gate is stricter than G2–G8** (each extra clause is satisfied by the 3 carriers; the census is unchanged at 3):
   floats are childless leaves with Display ∈ {absent, BLOCK} (LocalSelfAlignmentHandled propagates to descendants);
   container/floats/BFC tag ∈ {none, div} (UA margins); container Display ∈ {absent, BLOCK, FLOW_ROOT}, Position
   static, no Gap/RowGap/ColumnGap/multicol/BoxSizing/Float/Min-Max-InlineSize; BFC Display ∈ block set, Position
   static; G5's Clear refusal is subtree-wide; G7's contained arm also refuses SIZE / BLOCK_SIZE / PAINT containment,
   clipping overflow and any text in the BFC subtree (CSS wraps it at width 0, natively it would not); G8 extended to
   descendants — a painted descendant must be an inline-level px-wide atom (Appendix E step 7).
2. **G2 "no earlier root carries a Float" is not runtime-checkable** (the planner sees one container, like
   FloatClearance's attach gate). It is enforced as a corpus fact inside both censuses (and "the container is the last
   root"): 0 violations on both platforms.
3. **§10.6.7**: a container that is itself a BFC root reports max(BFC bottom, float bottoms); a non-BFC one (all 3
   carriers) the BFC bottom. M7 therefore reads "apply §10.6.7 to every container".
4. **M1**: the planner never reads a native measured width, so "drop containment" cannot produce the brief's (0,300).
   M1 is executed as "the G7 contained arm no longer requires inline-size containment" (red on the derived pin); the
   brief's (0,300) geometry is pinned separately by P8 (place() with the un-contained widths 200 / 300).
5. **P5 verbatim documents are refused by several clauses each** (`refusal-attribution.out.txt`), so deleting one
   clause (M4, M5) cannot turn them red. Each clause is isolated by a DERIVED pin — one exact, once-only edit of
   verbatim 001 (`P5d G2/G5/G7/G7/G8`) — and the mutations' reds land there. M9 (G8) and M10 (G2) are added.
6. P7/M8 is a pure-plan pin: the plan prefers the container's declared px Width over the incoming width (the captures
   already show the Column 400 wide on both natives — float 1 at x216).
