## 3. `--check`: what it does, and why it touches nothing (the wave-54 lesson)

- **Every mutating git call goes through `tree_mut()`.** In `--check` mode `tree_mut()` exits 70 before the call runs
  (B23–B25: a planted `tree_mut git status` trips it, and the tree is unchanged). Its sites are the records `git add` /
  `add -f` / `commit`, each unit's `git apply --index` and `commit`, and the restore's `git apply --index -R`. The script
  contains no checkout, reset, stash, clean or rm of the tree (grep over the source).
- **Every read of the tree is read-only:**
  - `rev-parse`, `symbolic-ref`, `log`, `cat-file -e`, `ls-files`;
  - `hash-object` without `-w`, which judges a path clean by content, so no index refresh is needed;
  - `diff-index --cached`;
  - `git apply --check / --numstat / --summary`.
- **"Applies on the current tree" is two `git apply --check` reads:**
  - each patch alone, where a STACKED patch is expected to fail alone (C3);
  - then the whole series as ONE concatenated input. git applies the files of one input in sequence in memory, which it
    does not do across separate input files (checked first in scratch). The first patch that stops the series is named
    (B12–B14).
- **The C12 revert dry-runs** (every selected unit's revertOrder, reverse-applied on the fully landed series) run in an
  EXPORT TREE:
  - a private `mktemp -d` under `$TMPDIR`, outside the repo (the script refuses a `$TMPDIR` inside the tree);
  - it holds copies of the touched files;
  - `git apply` runs there as a plain patch tool, with `GIT_CEILING_DIRECTORIES` set, so no repository is discoverable.
  - The dir is removed at exit (`ls $TMPDIR/land-units.*` → none).
  - The git-call log classifies every non-check apply as running inside that dir (A3).
- **The real path** runs every one of these reads first. It lands nothing unless the result is clean (B10, C14). It
  refuses (exit 2, nothing touched) when:
  - a gate, probe or A/B process runs in the tree (B26–B28);
  - something is staged;
  - a lane file was written less than 120 s ago (A7/A8).

- **Not exercised:**

    `diff-index --cached --quiet`.
  - The group pre-check that runs just before L2 U1's commit. The preflight's cumulative check already fails any series
    where U2 does not apply on U1, and a failure only that gate catches would need a patch to change mid-run.
- **The revert dry-run is stricter than `git revert`.** It needs exact reverse context, while `git revert` merges 3-way.
  A red dry-run can therefore be stricter than needed, but a green one is a sufficient proof (the plan asks for provable
  reverts).
- **What "busy" covers.** Busy means a `gate-driver` / `section-runner` / `test-all` / `provision-devices` /
  `ab-arms5N.sh` process whose cwd or command line is in this tree; an unknown cwd counts as busy. A gradle or xcodebuild
  sweep running in the tree is not detected. Land before the single-writer sweep, as in wave 54.
